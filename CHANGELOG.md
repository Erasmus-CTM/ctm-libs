# Changes

## Unreleased

- A worker that WebKit does not end on Stop now stops itself, also inside
  long C calls. The page gives each worker a blob URL and revokes it before
  it terminates the worker; the worker's interrupt buffer is a probe that
  loads that URL at most every 250 ms while Python runs (CPython reads the
  buffer every 50 eval-breaker checks). Once the URL is gone, the worker
  raises one KeyboardInterrupt, and if the program still runs a second later
  (it catches the interrupt), waits in a JavaScript loop, where WebKit ends
  it. Isolated pages' shared buffer works behind the probe. A program of long
  C calls finds out late (with 20 ms calls: about a second), one huge C call
  only at its end.
- Stop on a runaway program no longer leaves a busy thread behind in Safari
  and SEB on macOS and iOS. WebKit does not end a worker that is running a
  WebAssembly loop when the page terminates it; without cross-origin
  isolation (plain LAN HTTP), Stop is such a hard restart, so every Stop of
  `while True: pass` kept one core busy until the tab's process ended, and
  each later restart and the page got slower (the P13 WebKit acceptance saw
  a fourth restart take up to 146 s on a 3-core machine). The worker now sets
  a local interrupt buffer right after loading Pyodide, so CPython calls
  into JavaScript every 50 eval-breaker checks, where WebKit ends the thread.
  Isolated pages replace it with their shared buffer as before. A long call
  inside C code (a huge integer power, a builtin over a vast range) still
  runs to its end once terminated.
- `runtime/pyodide-sympy.json` records the SymPy version the pinned Pyodide
  bundles (0.28.3: SymPy 1.13.3), generated by `scripts/sync-pyodide-sympy.py`
  from Pyodide's own `pyodide-lock.json`; CI (`--check`) fails when it or the
  Pyodide pins drift. ctm-stack pins its build-time host SymPy to it, so a
  native PythonChecker question cannot be built against a SymPy the browser
  refuses (`python-checker-identity`). The browser smoke test reads its
  expected versions from the file.
- Generation requests may take 300 seconds instead of 180, and the time budget
  now applies to each provider request: a corrective retry after a rejected
  reply starts a fresh budget instead of inheriting what was left of the first
  call. Reasoning models used to time out regularly when a retry was needed.
  Ordinary feedback keeps 60 seconds per request.
- Shared Monaco preparation guards WebKit's proactive clipboard workaround
  when the API is unavailable or exam output is active. Both Python editors
  retain normal copy and selectable-text fallbacks without vendor-byte edits.
- With local assets (offline and exam builds) the worker points micropip's
  package index at a path of the site that does not exist, whenever micropip
  is imported: `micropip.install` of a package outside the served lock fails
  on the site instead of asking PyPI; locked packages install as before.
- `MathExerciseRuntime.ensurePyodide` in a worker loads Pyodide only from the
  base its page passes, `ensurePyodide({indexURL})` with the page's
  `MathExerciseRuntime.indexURL`; without it the call fails and nothing
  loads. Before, a worker (no `CTMAssets` there) fell back to jsDelivr
  without a word, also when its page used local or exam assets (review
  2026-11 L18). A worker keeps its first base and refuses another. Pages are
  unchanged. Workers that load the runtime with `importScripts` (stack-wasm-maxima's
  prototype at its next ctm-libs pin) pass the page's `indexURL`.
- Remove the ai-feedback extension alias and the metadata bridge for
  pyodide-interaktiv 1.8 (consolidation L3x). Install CTM Assessment and list
  `ctm-assessment`, or use standalone pyodide-interaktiv 1.9 or later.
  The generated forwarder template stays; stale ai-feedback 0.8.1 folders
  still trigger the migration message when listed beside CTM components.
- AI feedback typesets its math with the page's pinned KaTeX through
  `CTMAssets` (the local copy in a local-asset build) instead of the floating
  `katex@0.16` from jsDelivr; pages without CTM assets keep the release line.
- A local-asset build of a page with JSXGraph boards stops with a message:
  a board is a `data:` frame, where the local MathJax cannot load (until
  step 5b). An author HTTP `jsxgraph.src_mjx_preload` is refused in local
  mode like the other board URLs. The local-asset messages no longer name
  an installer option that does not exist.
- After the learner migrates a legacy math-exercise or pyodide-interaktiv
  feedback configuration and saves, the legacy record, which can hold an
  API key, is removed from both storages; unmigrated records stay importable.
- The filter-order message includes ctm-stack, as the package runs it.


### Added for components

- **ctm-checkers' STACK engine** (ctm-checkers 0.2, consolidation step 2):
  it has a wheel and page script of its own, so that pages with
  math-exercise never carry it. `ctm.checkers.use("stack")`,
  `ctm.checkers.wheel("stack")` and `ctm.checkers.environment(env, "stack")`
  add it for a component that grades STACK questions (stack-sympy); a
  ctm-checkers without it stops the render with the update command.
  `MathExerciseRuntime.ensureCheckers` and `callCheckers` keep one install
  per runtime and payload (`CTMCheckers`, `CTMCheckersStack`), so both work in
  one runtime, in any order: ctm-checkers installed after the STACK engine
  (or again, for a repeated call) replaces the package, so the runtime
  forgets the STACK engine and installs it again on its next call; the
  installs and the calls of one runtime run one after another, in one
  queue, so that no call runs while an install replaces the package (also
  with a component's direct `ensureCheckers`). The load after the install
  walks what the page's scripts installed, so a math page loads no STACK
  module.

### Added for authors

- **Reveals, in Markdown** (P18, F1): `::: {.reading-step title="…"}`
  ("Gå i dybden"), `::: {.hint}`, `::: {.solution}` and
  `::: {.details title="…"}` become closed boxes (`<details>`) in HTML, in
  the courses' look; `.details` is drawn related but distinct (a dashed line,
  no fill), since the switch leaves it alone. Titles are inline Markdown
  (a title such as "2. forsøk" stays as written), with default titles in
  English, German, Bokmål and Nynorsk for every kind. The colours are tints
  over the page, so reveals and the switch stay readable under dark themes,
  also one without a light twin. Headings inside a reveal stay inside it. AI
  feedback reads a reveal as it reads hand-written `<details>`. Other
  formats show reveals open, with the title in bold; `.solution` stays
  Quarto's Solution there.
- **The lecture/reading switch** (F2) appears at the top of every page with
  a reading step, or where `::: {.modes}` + `:::` puts it;
  `ctm-assessment: modes: false` leaves it out. The mode lasts for the
  browser tab, per course; printing opens the reading steps.
- **Embedded pages**: `::: {.embed src="…" title="…" height="920px"}` + `:::`.
- **Links into tabs and reveals, on by default** (AC): a link to a heading,
  an anchor or an exercise inside tabs or a closed reveal, from the page or
  from another page, also Back/Forward, opens every enclosing tab and reveal,
  scrolls the target into view below the header, keeps it there while the
  page settles, and focuses it. The browser's own jump to the fragment, which
  WebKit makes late on a busy page, lands there too, also after the tab row
  or the header reflows: a tab title's tab row stays in view, and the focus
  stays where the link put it (that jump leaves nothing focused when its
  target cannot take focus, such as a tab title's). A link wins over a
  grouped tabset's remembered tab without changing it, and keeps the focus. A reload returns to where the reader
  was, or, before the reader has scrolled, typed, clicked or touched, follows
  the link again: so does the reload with which coi-serviceworker makes a
  learner's first visit cross-origin isolated (hosts without COOP/COEP
  headers, such as GitHub Pages). Links to a tab's own heading need CTM
  Assessment's `tab-ids.lua` pre-ast filter.
- **Links into collapsed callouts.** A link to an id inside a collapsible
  Quarto callout (`::: {.callout-note collapse="true"}`) opens the callout
  too, alone or in any nesting with tabs and reveals (a callout inside a tab
  or a reveal, a reveal inside a callout, a callout inside a callout), and a
  link to the callout itself opens it, as a link to a reveal does. It opens
  through Bootstrap's own collapse, so the header's arrow and `aria-expanded`
  follow, and the rest of the link's behaviour (scroll below the header, focus,
  the late jump of WebKit) is unchanged. Before, the target stayed hidden and
  nothing was focused. As before, the script is loaded on pages with a
  tabset or a reveal; a page that has only a collapsible callout does not
  load it.
- **`ctm-assessment: markdown-lint: true`** warns at render time about raw
  HTML that has a Markdown form (`<details>`, `<summary>`, `<div id>`
  anchors, `<iframe>`, a hand-written switch), about tabsets without the
  `tab-ids.lua` line and about a `.details` without a title, naming files
  and lines. It reads nested includes where Quarto finds them: relative to
  the page (or, starting with `/`, to the project), not to the file that
  includes them.

### Changed for authors

- **Reveals take over six class names** (backwards-incompatible for a site
  that uses them; none of the CTM courses, the umbrella or its components
  does). In HTML, `::: {.solution}` is no longer Quarto's visible
  *Solution.* but a closed reveal, and divs with `.hint`, `.details` or
  `.reading-step` become closed reveals too. `::: {.embed}` becomes an
  embedded page (it needs `src` and `title`), and `::: {.modes}` the place of
  the lecture/reading switch.
- **Pages with a tabset load the tab links** (`ctm-ui.css`, `ctm-nav.js`;
  nothing else changes on pages without the new syntax).
  `ctm-assessment: tab-links: false` turns them off; a site that still has
  its own tab-link script sets it until it removes the script. `tab-links`,
  `modes` and `markdown-lint` take `true` or `false`; another value stops
  the render.
- **Render errors of ctm-libs are the message alone**, without a Lua file
  and line in front of it.

- **A build without AI feedback stops at exercises that only AI feedback can
  assess** (breaking for builds without AI feedback; there are no such sites
  yet). With `ai-feedback: enabled: false` or `CTM_FEEDBACK=off`, a page with
  `.ai-feedback` activities, or with a component's exercise that has no
  static check (a math-exercise in `mode: custom` without a `checker`, from
  the math-exercise version that asks ctm-libs), stops the build with one
  error that names every such exercise of the page, says that other pages
  may have more, and shows the setting that decides for all of them. A
  py-exercise without tests does not count: it still runs the code. The new
  setting `ai-feedback: without-ai:` (project, profile, `_metadata.yml` or
  page, the nearest winning) decides instead:
  - `text`: the question stays, without answer box and Check button, with a
    note that the exercise has no automatic feedback in this version
    (English, German, Norwegian Bokmål); the page's build message names
    them. Before, activities became `.ai-feedback-task` without a note.
  - `self-check`: accepted; the same as `text` until exercises have model
    answers to compare with.
  - `drop`: removes those exercises from the page; the build message names
    them and warns that links and cross-references to them no longer
    resolve. Only where you write it; it is never a default.

  Builds with AI feedback do not use the setting; another value stops both
  builds, naming the allowed ones. A CTM filter listed after
  `ctm-libs-end.lua` now stops a build without AI feedback, naming the
  expected order; with AI feedback a build warning names it.

- **pyodide-interaktiv 1.9 runs on ctm-libs** (consolidation step 3): its
  `pyodide:` options are a settings section (key by key on HTML pages, A1
  included; `1` and `0` keep their meaning; other values that broke the
  page's script now warn), its interface strings are the catalogue
  `pyodide-interaktiv` (byte for byte; `ctm-assessment: lang` applies; `nn`
  shows Bokmål), and its Python worker is ctm-libs' (below). On pages with
  Pyodide cells, other components' checks no longer wait for matplotlib and
  the other extra packages (D2): they download in the background without
  getting in a check's way; Pyodide's own cells and Run buttons wait for
  them as before. If they cannot be loaded, the status line says that plots
  are not available (naming the package), other Python code works normally,
  and Retry loads them again.
- **An old ai-feedback 0.8 next to CTM Assessment or pyodide-interaktiv 1.9**
  still stops the page, now with what to do: "AI feedback is part of CTM
  Assessment and of pyodide-interaktiv 1.9: remove ai-feedback from filters:
  and delete the old folder."

### For component developers

- `ctm.fail(message)` stops the render with a message for authors.
- `ctm.ui` (the page's interface, two passes of `ctm.filters()` before
  `ctm.feedback.prepare`), `ctm.sections` (the walk AI feedback's context
  follows: headings, tabs, scopes; lifted from `feedback.lua`) and
  `ctm.source` (the page's Markdown with its included files, nested ones
  too, resolved as Quarto resolves them, for messages that name a file and
  line). In the browser: `CTMNav.reveal(element)` and
  `CTMReveal`. A new catalogue, `ui`, has en, de, nb and nn.
- **For maintainer tools, what markdown-lint and the reveals read**
  (additive; no change to a page or a warning): `ctm.source.read(lines)`
  (one file's lines as the lint reads them: Markdown text without inline
  code and comments, or code, front matter and fences),
  `ctm.ui.rawHTML(lines)` (the raw HTML the lint names, by rule and line)
  and `ctm.ui.defaultTitle(kind, lang)` (a reveal's title without
  `title=`). `ctm.source.scan`, `markdown-lint` and the reveals' titles use
  them, so there is one implementation. They need no page: CTM Assessment's
  course converter runs them with `quarto pandoc lua` (docs/api.md, "Outside
  a render") instead of keeping a copy of these rules.
- `ctm.policy.withoutAI({component, kind, name, text, lang})`: a component
  asks about each of its exercises without a static check and gets nil (AI
  feedback on), `{action = "text", note}` or `{action = "drop"}`; ctm-libs
  keeps the setting, the names, the build message, the error and the note.
  Check that the function exists (older ctm-libs have none).
- **ctm-checkers**, the Python checker library of CTM Assessment
  (consolidation step 2): `ctm.checkers.require(component, api)` (stops
  with the install or update command), `use()` (the HTML dependency
  `ctm-checkers` with its page script, versioned by `checkers.json`'s
  `dependency`), `manifest()`, `wheel()` and `environment(env)` (the wheel on
  `PYTHONPATH` for build-time Python). In the browser,
  `MathExerciseRuntime.ensureCheckers(py)` installs it once per runtime with
  the install code of its page script and loads the whole library (learner
  code that deletes the installed wheel breaks no later call), and
  `callCheckers(py, name, request)` runs a call with a call text that looks
  up no name in the shared namespace (rebinding a name there does not affect
  it), installs again and repeats a call that failed before reaching
  ctm-checkers once (the request still in the namespace tells, no traceback
  needed), and leaves no `_ctm_` name behind. A runtime that was stopped or
  restarted (a stop on the page, or pyodide-interaktiv's restart event) gets
  no further call, since its terminated worker never answers: the call and
  those waiting behind it fail at once, and other runtimes are not held up.
  `_ctm_guard` keeps
  `ctm_checkers` modules; `scriptURL` is the runtime script's URL;
  `ctm.deps.folder(name)`; `ctm.deps.html` takes absolute paths of another
  installation's files. Check that `ctm.checkers` exists (older ctm-libs have
  none).
- **The bootstrap takes options** (`ctm-bootstrap.lua`, byte-identical in
  every component): `{standalone = "<install command>"}` for a component
  that also works without the package with the ctm-libs it ships (the
  messages then name that command; inside the package the package's
  messages apply), and `{api = n}`, the interface level it needs. Without
  options nothing changes, message for message. **`ctm.api` is 2**;
  components asking for 1 accept it.
- **CTMWorker** (`runtime/pyodide-worker.js`, dependency `ctm-worker`,
  `ctm.runtime.worker()`): pyodide-interaktiv 1.8's Python worker and its RPC,
  moved, with plugins (a component's worker-side commands, `capture` and
  `setPrompt`), the two start-up stages of D2 (`proxy.whenSetup`,
  `proxy.retrySetup()`) and the same proxy and globals (`qpyodideReady`,
  `qpyodideInstance`, `_qpyodideGetInstance`, `mainPyodide`,
  `qpyodide-runtime-restart`). `restart()` also rejects the old `whenSetup`
  (the error's `restarted` is true); later calls on the old proxy reject at
  once, and restarting it again returns the same new start. A stage-2
  install waits for a 300 ms pause in the commands, for 5 s at most, so a
  page that calls Python without pause cannot postpone the installs for
  ever, and a check shorter than 5 s meets at most one install. Installs
  take the prefetched bytes once their SHA-256 is the lock file's (the
  worker answers loadPackage's request itself), and the Cache Storage
  `ctm-pyodide-wheels` keeps them for the next page: the browser's HTTP
  cache is not involved (with jsDelivr's weak ETag and no Accept-Ranges,
  Chromium did not serve the full request from cached ranges). On a
  plain-HTTP origin (no crypto.subtle, no Cache Storage) the prefetch fills
  the HTTP cache as before. An install that Pyodide reports as
  failed ends stage 2 with its reason.
  `ctm.runtime.worker()` also writes
  `coi-serviceworker.js` (1.8's file, byte for byte) to the output root and
  adds its tag. `ctm.runtime.indexURL()` reads the one Pyodide constant of
  `runtime/pyodide-runtime.js`.
- `ctm.settings`: the section `pyodide`; `bool(..., {digits = true})` also
  takes 1/0 and true/false in any case. `ctm.locale`: the component and
  catalogue `pyodide-interaktiv` (en, de, sv, nb, da).
- `templates/ai-feedback`: the forwarder pyodide-interaktiv ships, so that
  updating replaces 1.8 projects' ai-feedback 0.8.1 folder
  (`filters: [ai-feedback]` keeps working with one warning).
- Without AI feedback, the bridge's "pyodide-interaktiv feedback" goes into
  the build message only when pyodide-interaktiv did not ask itself (1.9 asks
  under an explicit `pyodide: feedback: true`): Pyodide is named once.

## 0.9.0 (CTM Assessment 0.9.0)

The ai-feedback repository becomes **ctm-libs**, the internal library of CTM
Assessment: AI feedback folds into it, and it takes over what the components
shared or copied (settings, languages, the Python runtime, the dependency
locator). Course authors install CTM Assessment only.

### Changed for authors

- **Settings combine key by key in every CTM section** (`ai-feedback`,
  `ctm-assessment`, `math-exercise`, `py-exercise`): a page that sets one
  option of a section keeps the project's other options of that section
  (F-79). Before, a page's own `math-exercise:` map dropped the project's
  `feedback` and `stop-after`.
- **A credential in the metadata stops the render** (`api-key`, `token`,
  `secret`, ... in any CTM section; A1). It was a warning.
- **Two policy keys** (A2): `policy-files` adds up over project, profiles,
  `_metadata.yml` and page; `policy` selects, the nearest setting winning.
  `project-policy`, `page-policy` and `page-policy-files` keep working in 0.9
  with a warning each.
- **Unknown `ai-feedback:` and `ctm-assessment:` options** warn that they
  become errors in 1.0 (A3); `version:` is not an option (A7).
- **Explicit context also sends the section's prose** (A5): with
  `context: notes`, the feedback request holds the listed blocks and then the
  prose of the exercise's own section, without context blocks (the listed
  ones come first, the others belong to other exercises).
- **The AI context stays in the exercise's tab and leaves out closed
  material**, for automatic and explicit context alike: a tab of a tabset
  starts a section as a heading does (nested tabsets too), and after a
  tabset its section goes on without the tabs' prose; the content of
  `<details>` blocks and collapsed callouts (solutions, reading steps,
  hints) is not sent as section prose, except to an exercise inside such a
  block. Before, automatic context could carry other tabs' prose and closed
  solutions. This changes what a feedback request contains, not grading.
- **A site without AI feedback** (P22): `ai-feedback: enabled: false` (for
  example in a profile) or `CTM_FEEDBACK=off`. No page can turn it back on;
  nothing of AI feedback reaches the HTML; pages that asked for it get one
  build message.
- **New key `ctm-assessment: lang`**: the interface language of every
  component. Pages in Nynorsk (`nn`) get the Bokmål interface; region tags
  are understood everywhere (`de-CH` → German).
- **Scripts are cacheable files**: the runtime, the catalogues and the
  feedback files are HTML dependencies, loaded once per page.
- **`filters: [ai-feedback]` is deprecated**: it keeps working in 0.9 with
  one build warning. Use `filters: [ctm-assessment]`.
- **Pyodide 0.28.3** (Python 3.13, SymPy 1.13.3 as before) for the page's
  Python runtime, the version pyodide-interaktiv already uses (D4). On pages
  with pyodide-interaktiv the components use its Python, so a project that
  pins `pyodide: base-url` keeps that version there.
- **A component without CTM Assessment stops** with the install command
  (components' `ctm-bootstrap.lua`; `CTM_COMPONENT_DEV=1` for component
  development).
- Values that were accepted loosely (`py-exercise: submission`,
  `show-test-hints`, `feedback`; a component section that is not a mapping)
  warn that they become errors in 1.0.

### Unchanged
